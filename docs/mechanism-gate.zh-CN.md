# 核心机制验证：现有证据未通过

核查日期：2026-09-27。研究方向保持为“动态智能体任务的本地—云端可信执行与任务所需信息共享”。本文件记录研究关口的实际结论，不是新版论文，也不宣称达到技术 8—8.5 分、实验至少 8 分。

## 本轮完成的受控比较

此前三组任务完成数为 5/6、4/6、6/6，但各自来自不同模型和模拟用户轨迹。不能直接将差异归因于受限引用。

现在对最后一次普通引用、受限引用两组的全部记录做离线干预：每条轨迹在两个全新原始业务数据库中分别执行；两边仅改变引用用途/来源新鲜度检查，固定模型提案、已有观察和本地用户确认。使用各批次冻结的引用与确认代码。随机引用名建立一一映射，防止随机字符串被误认为算法差异。原方法一侧必须逐步重现已保存的原始参数、返回值和数据库哈希。

若两侧第一次出现不同结果，则立即停止该轨迹；后续模型和用户本来会看到不同结果，不能继续把保存动作当作有效的新对话。检查器本身包括能触发用途拒绝的单元测试、相同确认/拒绝的测试，以及篡改参数与确认内容的负面测试。这些是检查器正确性测试，不计入业务成功率。

## 排除三个无效的提升路径

1. **继续只增加引用范围或来源版本检查。** 有工程价值，且可以构造触发它的程序测试；现有自然轨迹没有体现收益，已有门控设计也高度相关。不能将人为注入错误的单元测试当成真实任务改进。
2. **重新命名本地查询融合、聚合或延迟求值。** v9 的强基线已有同样本地查询能力；现有纯查询段可以等价地在本地合并后只发送最终结果。更换实现语言不改变这一点。
3. **增加模型、任务数或反复运行直到成功。** 可以在机制固定后增强证据，但不会产生机制差异。开发失败必须保留，不能挑成功轨迹替代独立测试。

## 后续研究必须回答的具体问题

需要在原方向内明确一个尚未解决的必要性判定：动态出现的语义步骤需要什么信息、当前表示是否充分、失败后为什么需要补充某项信息。候选实现必须给出输入、输出、假设和误判边界，不能把模型自称“信息充分”当作证明，也不能用评价答案反推应该发送什么。

合理强基线可以与候选共享工具、查询表达能力和用户确认。这不要求证明基线“在理论上绝不可能模拟”候选；前几版的这一要求过强。真正需要的是可复现的改进，例如同等质量下更少的实际外发，或同等外发限制下更可靠的任务完成，并解释改进来自何处。若基线已有相同优化并达到相同结果，则没有新增收益。

正式测试前，必须冻结评价规则。独立测试按源任务/合同/客户分组，重复轨迹不增加独立样本数；真实任务、合成压力用例和人为注入故障分开报告；自然语言质量仍需要已安排的真人评阅。不能用字节下降代替语义隐私，也不能用数据库哈希一致代替所有业务政策都满足。

任务来源也需要匹配研究问题：tau2 的原始业务任务适合测试多轮执行与状态正确性，本轮没有为它获得独立的“每个接收方需要哪些语义事实”标注，因而六类字段计数不能充当任务必要性的真值。[ToolPrivacyBench](https://arxiv.org/abs/2606.28061) 提供了按字段、工具和用途评价的相关设计；其论文将授权知识库用于事后评价，不能读取该评价库来决定我们的运行时策略。在本次核查的正文中，作者表述为将发布代码与完整数据；本轮未取得并运行其完整数据，不把它列为已完成实验。

另检索到 [MID](https://arxiv.org/abs/2608.02774)，但其主要对象是模型/硬件执行的验证证据，不能只因标题包含“最小信息”就称与智能体运行时方法相同。它提示评价应区分授权结果本身包含的信息与额外信息；本项目尚未实现其信息论指标。

已进一步准备 [PrivacyLens](https://github.com/SALT-NLP/PrivacyLens/tree/9c2ee07b080dc54ed4924af11d9751e81753c94d) 的外部候选输入：固定提交的 493 条来源记录，按完整的精确隐私规范分组，40 条开发候选、453 条预留。运行输入以白名单生成，隐私规范、敏感条目和预期动作单独保存用于评价。完整来源和输出摘要见 [候选材料](../evidence/input-candidates/README.md)。未运行模型、评判器或新业务后端，不能把 493 条记为实验量。它可补充最后一步的隐私规范评价，但这些标签也不是所有信息的最小充分性真值。

## 本轮关口决定

受限引用候选未通过核心贡献验证，因此没有把 6/6 写成检查带来的成功收益。中文 Word 已按用户要求同步真实结果：加入末批业务实验表、固定轨迹的零变化结果及相应限制；修订文章不再以证明新算法优越为前置条件。现有 UI 保持已确认版本。新增的登记需求执行器已有构造 HTTP 检查，未计入模型实验，也未被描述为通过了独立任务验证。

技术 8—8.5 分与实验至少 8 分仍为目标，当前尚无依据承诺已经达到。新的有效机制与独立测试是实质未完成工作；排版、跨模型调用和 README 装修不能消除这一缺口。

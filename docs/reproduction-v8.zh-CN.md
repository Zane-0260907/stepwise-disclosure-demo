# 真实模型计划与按步执行复现

本轮把真实 DeepSeek 工具调用、执行图、条件变化、结果保留和实际接收内容接在一起。核心仍是**每一步在哪里执行、向当前接收方发送什么**。它是独立研究实现，不包含商业客户端和账号密钥，也不需要开源 DeepSeek 模型。

## 一 启动与观察

安装 Node.js 24，在终端执行：

```sh
git clone https://github.com/Zane-0260907/stepwise-disclosure-demo.git
cd stepwise-disclosure-demo
npm ci
npm start
```

打开 http://127.0.0.1:4793/，保持终端运行。

1. 选择“真实模型计划 · 本地能力变化”和“约束重复传输 · 保留有效结果”，点击开始。
2. 左侧载入保存的真实模型调用，创建三步计算。模型原本先请求表结构，再提出“相加、相加、相除”。
3. 第一步在本地完成后，预定干预撤销本地算术能力。已有正确中间值保留，剩余步骤转交 HTTP 算子。
4. 点击最后的相除步骤：右侧显示阶段预算、实际发送的中间值和源值，以及接收端保存的原始请求。
5. 改选“条件变化后全部重跑”，再运行一次，点击“查看同案例对照”。观察同一条件下重跑了哪一步，而非只比较最终答案。
6. 再看“已用源值更新”和“未用源值更新”。前者应使有关结果失效，后者可以保留已有计算。步骤自动推进；查看旧步骤后，可点击“跟随当前步骤”。

该模式**复用保存的真实模型计划，但重新执行计算和 HTTP 请求**，不会产生新的模型费用，也不是只播放预设结果。页面和下载记录明确区分保存调用与本轮执行。HTTP 接收端和控制器位于同一 Node 进程，是实际回环请求，不是生产云服务或独立进程认证。页面的放慢展示不计入实验耗时。原始财务问题、表结构和模型响应保留原文，中文和英文界面共用同一执行状态。

## 二 无密钥复算全部实验

Windows PowerShell，在仓库根目录执行：

```powershell
Expand-Archive -LiteralPath evidence/validation-v8/reproduction-records.zip -DestinationPath . -Force
npm run verify:v8
node scripts/analyze-v8.mjs
```

Linux 或 macOS 将第一行换为：

```sh
unzip -o evidence/validation-v8/reproduction-records.zip -d .
```

核验器会检查冻结文件摘要、实际供应商请求和响应、模型工具调用与执行图的对应关系、每条 HTTP 请求、源版本、中间结果、执行能力和阶段预算，再用独立算术解释器复算。不要直接使用原冻结核验器；发布入口已修正“重复相同请求错误匹配第一次回执”的问题，详见[修订说明](../evidence/validation-v8/verifier-amendment.md)。原代码、数据和评分口径全部保留。

| 核对项 | 本次发布结果 |
|:--|--:|
| 公开问题 / 此前未用公司年度报告 | 24 / 24 |
| 真实 DeepSeek 调用 / 模型计划 | 96 / 48 |
| 条件 × 方法 × 计划 | 5 × 6 × 48 = 1,440 |
| 原始问题的标签一致性 | 28 / 48 |
| 每方法执行完成且符合模型程序 | 240 / 240 |
| 每方法符合变化后参考程序 | 137 / 240 |
| 完整重跑 / 局部修复的外部调用 | 331 / 261 |
| 完整重跑 / 局部修复的数值字段传输 | 724 / 500 |
| 贪心 / 后续规划 / 默认预算的不同披露项 | 425 / 425 / 425 |

每份模型计划在 30 个配对执行分支中共用其两次原始调用，**不能把 96 次调用再乘 30，也不能把 1,440 次执行称为独立模型样本**。模型收到的是问题、表结构、年份和单位，未收到业务数值字典；这些元数据仍然属于披露内容，不是“零信息外发”。

## 三 自备密钥运行新批次

PowerShell 可以隐藏输入密钥：

```powershell
$v8Secret = Read-Host 'DeepSeek key' -AsSecureString
$v8Credential = [pscredential]::new('local', $v8Secret)
$env:DEEPSEEK_API_KEY = $v8Credential.GetNetworkCredential().Password
try {
  npm run experiment:v8 -- --run-id=my-v8-run
} finally {
  Remove-Item Env:\DEEPSEEK_API_KEY -ErrorAction SilentlyContinue
  $v8Credential = $null
  $v8Secret = $null
}
npm run verify:v8 -- --run-id=my-v8-run
```

新结果保存在 `data/research/validation/my-v8-run/`，不会覆盖发布结果。相同运行名会读取已保存记录，模型失败同样保留，不挑选重试。要重新收集一批，换一个运行名；不要同时启动相同运行名。模型为 `deepseek-flash`、温度 0、非思考模式，计划产生 96 次付费调用。模型更新和非确定性可能使新结果不同。

密钥仅由本地进程使用；公开的是调用载荷、模型原始回复、执行过程和结果。不要把密钥写入 README、代码、截图或提交文件。无密钥体验和历史数据复算完全不需要账号。

## 四 六个方法实际比较什么

- **完整重跑**：状态改变后丢弃已完成计算；模型图、源数据、候选视图和检查条件保持一致。
- **逐步贪心修复**：保留有效结果，每次只选当前步骤的输入形式。
- **后续规划修复**：保留有效结果，比较当前已知图的等价输入组合。
- **预算 0%、10%、25%**：在后续规划上限制本阶段数值字段次数；按该阶段贪心方案设定额度，并逐步扣减余额。

阶段预算不等于整轮任务预算，不限制原始 HTTP 字节，也不是隐私损失定理。原始字段和派生值按接收方及源版本标识；重复发送虽然不增加同一披露项，仍消耗传输额度。源值、能力变化与全部本地配置都是预定实验条件，不伪装成模型自主发现的故障。

## 五 应如何理解结果

局部修复相对完整重跑减少 21.1% 的外部调用，复用 112 个结果；**本批次没有观察到后续规划优于强贪心，三档预算结果也相同**。不能把已有的结果复用收益归因于新的规划目标。

48 份计划都能执行，仅 28 份与原始标签一致。错误包括字段、年份、方向和单位；两道平均数题的原始标签程序还疑似存在问题。目前不修标签、不删样本，也不把标签一致率当成人审确认的语义正确率。[20 条不一致记录](../evidence/validation-v8/disagreements-for-review.json)包含原题、原表、原标签和模型程序，等待独立评阅。

样本来自受限公开 FinQA 子集，12 题原属 test、12 题原属 dev，来源划分如实保存；不是生产数据，公开材料也可能进入模型训练。原始字节数包含方法名长度差异，补充分析另给去掉 `runId` 后的载荷长度，不能把运行标签长度当成算法收益。

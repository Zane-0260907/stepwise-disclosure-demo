# 后续相关披露状态压缩 验证协议

日期 2026-09-28。实现前记录。方向保持为动态智能体的执行位置与接收方输入选择，不把本轮变成文档检索系统。

## 研究问题与可证伪主张

同一已知任务图可以用原始字段、派生值或本地计算完成。在有限登记候选内，目标依次最小化新增不同披露项、求值工作量和发送字段次数，并受同阶段传输预算限制。旧规划器保存每个前缀的完整披露集合，已经不会在后缀出现的项目仍使状态不可合并。

新算法在每个边界只保留后缀仍可能使用的新增披露项，将其余项目转成不可撤销的计数。**完整接收方披露历史仍保存在运行时，不被删除。** 新步骤出现时，使用完整历史重建当前已知图的规划状态；不预知尚未出现的步骤。

要检验的主张是：在相同候选、预算与成本定义下保持最优值，降低某些低边界宽度任务的搜索状态及规划开销。它不声称发明动态规划、求得自然语言的最小充分信息、降低推断隐私风险，或保证所有图都快。

## 比较方法与失败记录

- 逐步贪心：同样的候选、缓存和执行能力。
- 完整集合前沿：仓库旧精确规划器，不改其结果来制造差异。
- 后续相关状态压缩：本次实现。
- 独立 MILP：使用 SciPy/HiGHS，将候选选择与披露项目并集写成整数规划。所有方法接收同一输入和预算。
- 小问题穷举：逐一遍历候选组合，单独验证正确性，不作为大规模性能方法。

共同标签上限 4096。整数规划每例最多 10 秒；未求得已证明最优解、超时、内存/标签上限及无可行方案均分别报告。算法不读取任务答案来规划。

## 材料及计数

1. 既有 FinQA 真实模型计划仍保留全部 48 份及错误，不重复计为新模型调用。用于在原来任务上验证兼容性与零新增收益。
2. 来源明确的公开 FinQA 表格及计算程序可作为查询执行输入；程序来源是标注，不能称为新生成的模型计划。按来源报告分组，不把组合查询或条件变化算作独立自然任务。
3. 独立合成规划工作负载：覆盖前缀唯一项目、跨步骤共享、宽重叠、局部能力、接收方区分、预算紧张与不可行情况。控制图长度和披露边界宽度，说明它们是设计的负载，不能估计生产场景频率。
4. 动态 HTTP 集成：真实重新执行已知图，随后加入新步骤或改变来源/能力，核对实际请求、计算结果及累计历史。展示放慢不计入运行时间。

开发种子从 11000 开始；正式合成验证种子从 71000 开始；穷举测试种子从 31000 开始。修复实现错误须记录并重新冻结后重跑全部正式记录，不挑选成功样本。

## 评价与正文入口

评价顺序：最优值一致性 → 未完成率 → 规划时间及峰值状态 → 实际披露与传输代价 → 原始任务答案。分别报告低宽度与高宽度条件，不用总均值掩盖算法退化。时间仅反映当前硬件，发布机器信息和原始逐次时间。

论文以核心问题、有限方法及保证、交互演示、分层证据四部分组织。旧模型任务结果与新算法实验分开；失败候选放开发记录，不继续占据正文核心。正文仍为中文四页、原生 Word 公式与英文伪代码，延续已认可的 UI。

## 本轮固定自评规则

自评不是会议分数或接收概率，不能因用户目标改变权重。六项等权，逐项给依据和扣分项：问题与会议契合度、技术贡献、实验说服力、文字论证、演示与图文版面、开源复现。平均目标至少 8；未完成的人审、ORCID、视频保持独立待办，不能虚构完成。技术贡献评价具体机制及已有工作边界，不以更换语言、代码量或 API 次数加分。

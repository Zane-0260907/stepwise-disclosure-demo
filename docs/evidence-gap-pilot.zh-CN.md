# 证据缺项补充：开发检验协议

状态：候选方法的开发检验，不是正式测试或新颖性结论。2026-09-28。

## 要验证的改变

原方向仍是动态 Agent 的执行位置与当前接收方输入控制。本次只检查其中一个必要环节：本地文档中的明确交叉引用，能否成为补充输入的可核对理由，减少依靠云端反复猜测需要哪些原文。它不替代整个 Agent 系统，不改变已确认界面。

候选控制器在模型提交有来源的证据片段时，从**该片段实际包含的引用**生成待补充项。本地解析器查找对应来源；唯一找到且尚未发送的目标片段才进入补充集。存在歧义、找不到目标和预算耗尽分别记录，不能由模型自称“需要更多信息”放行任意原文。随后模型读取补充内容继续任务。

本轮解析器只定位明确编号引用的标题所在片段，不保证整节已覆盖；不自动解析附件外文件、定义链或任意自然语言缺项。明确指向其他文件或指向不明文件的引用不套用本文件的同名编号。规则解析会漏检，需在逐例分析中报告。

开发修订：第一批真实调用发现模型经常一次返回多个独立检索调用。原执行器的单调用断言使部分尝试失败。原记录与冻结代码保留；第二批对所有方法共用顺序批处理（每条模型消息最多八个工具调用），不将该执行器修复归为候选算法收益。

第二批暴露了证据引用接口问题：模型会合并原文中的空白、引用横跨相邻片段的句子，严格的单片段字符串检查导致重复重试。第三批对所有方法统一采用仅空白归一化的坐标定位，只接受**已发送原文范围内**的唯一匹配；返回真实来源原文，并保留模型提交的原引文。词、数字、标点和否定词不做模糊匹配。连续三次相同工具拒绝停止，避免无效重试消耗预算。这也是共同接口修复，不是候选方法的收益。

与旧版区别：不枚举事先手填的 `aboveLimit` 等表示，不比较纯查询的延迟返回时机，不把用途/版本检查重新命名。候选自动处理提交证据暴露出来的结构缺项。**存在引用并不证明其内容在语义上必要；引用齐全也不证明答案充分或正确。** 引用图及检索是已有技术，本次不能以采用它们本身宣称新算法。

## 对照与公平性

四方法共用模型、系统提示、文档划分、BM25 检索、批量引用解析、源片段读取、提交检查与调用上限：

1. `full`：初始提供完整原文。
2. `static`：初始提供固定检索视图，后续只能提交答案；作为一次性裁剪对照。
3. `on_demand`：按需强基线；可反复检索、按精确位置读原文、批量解析引用。提示明确建议核查重要引用。
4. `gap_repair`：同样的工具；提交时对引用中的缺项自动执行与强基线相同的批量解析，然后请求模型重审。

`static` 是受限诊断对照，不冒充最强基线。正式判断必须比较 `on_demand` 与 `gap_repair`。不得删除基线的局部查询、引用解析、批处理等能力。双方初始输入完全相同；首次产生不同观察之后必须分别调用模型，不能继续复用同一后续轨迹。

## 输入、评价与预算

- 来源为已固定 SHA-256 的 CUAD 公开合同及原问题。仅使用官方训练来源，排除 v9 已用的八份合同。
- 按固定盐的来源标题哈希选 24 份合同，原文字数 6,000—60,000。六类问题轮换分配；不按答案存在与否、引用是否匹配、候选是否胜出筛选。
- 任务输入只含原文和问题。答案跨度单独保存在评价文件；运行模块不读取它。没有读取官方测试集作为本轮调参数据。
- 先跑固定顺序前四例、四方法，共 16 次尝试。每次最多 8 次模型调用；禁止自动扩展为整个批次。批次调用及 token 上限显式设置。
- 来源坐标统一采用 Unicode 码点，避免 Python 与 JavaScript 对非 BMP 字符的偏移解释不同。
- 主开发指标为原标注跨度字符覆盖的 precision / recall / F1、回答是否为空、引用原文有效性、独立来源文档数。额外输出会降低 precision；不使用只取最佳片段而不罚冗余的旧指标。
- 这是本项目的跨度诊断，**不是 CUAD 官方排行榜分数，也不是法律意见质量或最小充分性真值**。
- 实际发送的不同源字符、累计重传源字符、全部请求字节、token、调用次数及时间分开统计。原文是公开材料；字数下降不称隐私改善。
- 失败、超时、预算耗尽全部保留。无输出计零 F1（即使金标准为空），防止崩溃被算成正确拒答。
- 初始全文对照允许全文，其余三组使用相同的累计源字符预算。应报告这一不同设置，不把全文与受限方法的差异当核心机制增益。

## 无密钥时能做什么

可以准备输入、审计解析器、复核保存结果、运行单元测试。这些不能记作 DeepSeek 调用或任务正确率。没有新的实际模型记录，就不产生候选效果分数、不重写论文结论。

## 继续与淘汰条件

开发比较要逐例列出：第一次不同决策、实际补充的来源、是否改善跨度质量、增加多少外发和调用。若只是多给了原文才提高分数，需做相同外发预算比较；若强基线已等效处理，则不增加一个新算法名称。

小样本只能决定是否值得继续。正式独立验证的来源分组、样本量、自由文本人工评阅与统计检验需在候选固定后另行冻结。本轮不据开发结果承诺技术 8 分或实验 8 分。

- [CUAD](https://arxiv.org/abs/2103.06268)：原任务是合同片段识别；不提供本研究的隐私或语义充分性标签。

## 运行入口

```sh
python scripts/prepare-gap-pilot.py
node scripts/audit-gap-inputs.mjs
node --test test/evidence-gap.test.mjs
node scripts/run-gap-pilot.mjs --run-id=gap-canary-01
python scripts/score-gap-pilot.py --run-id=gap-canary-01
node scripts/verify-gap-pilot.mjs --run-id=gap-canary-01
```

现场运行需先在本机配置 `DEEPSEEK_API_KEY`，运行 `node scripts/start-native-proxy.mjs`。密钥、代理令牌与连接文件不进入证据包或仓库。运行器只接受回环代理地址，记录请求正文和返回正文但不记录认证头。

Windows 也可以运行 `powershell -ExecutionPolicy Bypass -File scripts/start-native-proxy.ps1`，在本机隐藏输入密钥；保持该窗口运行。它不将密钥保存到磁盘，关闭后清除本进程临时变量。启动后另外一个终端执行上述实验命令。

核验脚本从冻结的运行模块重新执行本地选择，把每一个重建请求与保存请求逐字节比较，并为每次有响应的调用匹配不同的供应商传输记录。核验只使用已保存返回，不冒充新模型执行；调用失败且没有供应商记录的请求仍不能确认最终计费或接收状态。

## 因果归因核查

对强基线和候选共八条末批轨迹，保持每一步已有模型返回不变，仅切换自动补充开关。下一次请求若发生变化，核查器会立即停止，不再把旧回复应用到新观察。实际八条轨迹都没有发生变化，最终输出一致；候选自动补充触发次数为零。核查过程没有新模型调用。

因此，独立运行之间的检索范围差异不支持“新增控制器减少披露”的说法。这个结论只适用于已观察轨迹，不证明所有任务上永远无效。

## 暴露的研究问题

1. **显式引用不是充分的缺项信号。** 许多任务没有此类引用，或者强基线本来就通过搜索与阅读取得了相关内容。
2. **拿到更多原文仍可能答错。** 两个 CUAD 原标注为空的任务，模型仍返回了片段；在已有完整原文的尝试中也出现这种标注不一致。追加原文不能自动解决任务语义判断。
3. **当前任务主要是静态合同片段识别。** 它可以检验来源与引用模块，却不能独自证明动态企业 Agent 的位置选择、接收方变化与必要信息控制。
4. **已有技术重合。** 图检索、引用定位和提交前再检查均不能仅靠新名称成为核心新颖性。

## 研究决定

淘汰“仅靠显式引用补充”作为论文核心贡献的候选；不扩大付费批次，不给它生成优势图，不将结果写成创新收益。相关代码和负结果可保留作基线与可复核开发记录。

下一候选必须在实现前给出与本次不同的可操作信号：能区分“尚缺证据”“已有证据但推理错误”“原文没有答案”，且不能读取评价标签、把同一模型的自我保证当独立正确性证明，或通过拒绝全部任务获得少披露。必须覆盖真正的动态步骤与接收方；静态抽取分数只能作局部检查。

这仍是未完成的核心研究任务。技术 8—8.5、实验至少 8 的目标没有达成；此记录不把一次排除候选、工程修复或更多 API 调用描述为已经解决问题。
